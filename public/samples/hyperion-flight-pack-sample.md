# Bounded work order sample

Illustrative excerpt only. A paid Flight Pack uses the buyer's objective, bounded scope, acceptance criteria, and verification method across each generated document.

## Objective

Improve one existing project workflow while preserving its current data and user-visible behavior.

## Allowed scope

- Inspect the named repository and report its current state.
- Implement the smallest complete change needed to meet the acceptance criteria.
- Run the declared verification and review the final artifact.

## Out of scope

- Unlisted systems or repositories.
- External communication, deployment, publication, or payment without human approval.
- Destructive changes without a reviewed rollback plan.

Stop and report when scope or assumptions change. Hand off files, checks, evidence, risks, and remaining decisions.
